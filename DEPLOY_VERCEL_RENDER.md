# Deploy the frontend on Vercel and the backend on Render

This deployment keeps browser requests same-origin by having Vercel proxy
`/api/*` to Render. That is important because authentication uses an HttpOnly
cookie. PostgreSQL stores users, portfolios, saved valuations, and learning
progress persistently; SQLite remains available for local development only.

## 1. Push this branch

Commit these deployment files and push the branch you want Render and Vercel to
deploy. Never commit `backend/.env`.

## 2. Create the Render backend and PostgreSQL database

1. In Render, choose **New > Blueprint** and connect this Git repository.
2. Select the deployment branch and let Render read `render.yaml`.
3. Enter these secret values when prompted:
   - `GEMINI_API_KEY`: the Gemini key used for AI explanations.
   - `RESEND_API_KEY`: the key used to send login codes.
   - `RESEND_FROM`: a sender authorized in Resend, for example
     `PSXviewAI <login@your-domain.com>`.
4. Apply the Blueprint. It creates `psxviewai-api` and `psxviewai-db` and links
   the internal PostgreSQL connection string as `DATABASE_URL`.
5. Wait for the health check to pass, then open:
   `https://YOUR-RENDER-SERVICE.onrender.com/api/health`.

`JWT_SECRET` is generated by Render and `COOKIE_SECURE=1` is already configured.
Python is pinned to 3.13.15 because the project's binary dependencies are not
intended to build against Render's newer default runtime.
Use Resend rather than SMTP on Render. Without valid Resend settings, OTP codes
will not arrive by email.

The Blueprint currently selects Render's free plans for initial testing. A free
Render PostgreSQL database expires 30 days after creation and has no backups.
Upgrade the database before then if you need to retain production data.

## 3. Configure the Vercel API proxy

After Render gives you the exact backend URL:

1. Copy `vercel.json.example` to `vercel.json`.
2. Replace `YOUR-RENDER-SERVICE` with the exact Render subdomain. Keep `/api/:path*`
   on both sides of the rewrite.
3. Commit and push `vercel.json`.

Example destination:

```json
"destination": "https://psxviewai-api-abcd.onrender.com/api/:path*"
```

Do not put API keys or the PostgreSQL URL in Vercel. They belong only in Render.

## 4. Deploy the frontend on Vercel

1. Import the same Git repository in Vercel.
2. Select the same deployment branch.
3. Keep the project root as the repository root.
4. Vercel should use:
   - Framework: Vite
   - Build command: `npm run build`
   - Output directory: `dist`
5. Deploy. No frontend environment variables are required for the API URL,
   because `vercel.json` performs the proxy rewrite.

## 5. Verify production

Open these URLs in order:

1. `https://YOUR-VERCEL-DOMAIN.vercel.app/api/health`
2. The Vercel home page and market data.
3. Register with an email address and verify that the six-digit code arrives.
4. Sign in, add a portfolio holding, refresh, and confirm it remains saved.
5. Request an AI explanation and confirm its source is not the fallback.

If step 1 fails, verify the Render URL in `vercel.json`. If OTP email fails,
inspect the Render logs and verify `RESEND_API_KEY` and `RESEND_FROM`. If AI uses
the fallback, verify `GEMINI_API_KEY` and the configured model.

## Local development

No local PostgreSQL installation is required. With no cloud `DATABASE_URL`, the
backend continues to use:

```env
DATABASE_URL=sqlite:///./psxviewai.db
COOKIE_SECURE=0
```
